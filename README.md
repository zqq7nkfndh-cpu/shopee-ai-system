# Shopee Research Desk

日本からShopeeで越境ECを行う、個人向けのリサーチ・採算判断・出品準備Webアプリです。日本語UI、スマートフォン向けレイアウト、パスワード認証、SQLite保存に対応します。

**自動出品・仕入れ・支払い機能はありません。** 国ごとの数値を入力して判断し、最後はSeller Centerで確認・操作します。APIキーなしで基本機能がすべて動きます。

## ローカルで起動

Python 3.12以上を用意し、リポジトリのルートで実行します。

```bash
python -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.lock
python -m shopee_workbench serve
```

Windowsでは有効化を `.venv\Scripts\activate` に置き換えてください。起動時に**12文字以上のパスワード**を入力し、[http://127.0.0.1:8000](http://127.0.0.1:8000) を開きます。同じパスワードで画面にログインします。パスワードは入力中表示されません。ローカル開発サーバーはPC自身からのみアクセスできます。

環境変数 `APP_PASSWORD` またはWerkzeug scrypt形式の `APP_PASSWORD_HASH` があればパスワード入力は省略されます。`.env.example` は設定項目の例です。ローカル起動は `.env` を自動読込しません。必要な変数をシェルで設定してください。

`python main.py serve` でも起動できます。ポート変更は `--port 8080`。データベースの既定パスは `var/workbench.sqlite3`、変更は `DATABASE_PATH` 環境変数です。

## 最初の使い方

1. **設定**で対象国の費用・為替・課金基準を入力します。費用がない項目も0と明示してください。出典URL・確認日とともに確認済みにします。最初の数値は空欄で、公式料率の初期値はありません。
2. **商品リサーチ**で候補を登録します。旧版の着想カタログ、CSV取り込み、販売国を変えた複製も使えます。需要・競合は観測元URL・観測日・検索条件を記録し、未取得値は空欄のまま残します。
3. 商品詳細の**利益分析**で、現地売価・原価・送料・梱包・関税・その他経費を入力します。利益、損益分岐、目標利益率の価格、為替・送料・売価悪化時の利益を確認します。
4. **出品コピー**で英語名・確認済み英語仕様を入力して定型案を作るか、手動編集します。任意で `OPENAI_API_KEY` と `OPENAI_MODEL` をサーバーに設定するとAI案を生成できます。生成は明示的なボタン操作のみ。案の取り込みと保存は別操作で、既存の文章を勝手に上書きしません。
5. **出品前チェック**で規制・権利・販売資格を確認し、状態を**承認済み**にします。画像URL、カテゴリID、梱包重量・寸法、実在庫、物流、本文を揃え、国別の最新テンプレートを確認して**出品準備完了**にします。
6. **出品準備**から国別の**転記用CSV**を作ります。これは公式一括アップロード形式の保証があるファイルではありません。最新のSeller Centerテンプレートに転記し、最終確認後に手動で出品します。

重要な商品情報や国別条件を変えると、承認済みの商品は調査中へ戻ります。本文・仕入れ先等の変更後は、保存してから確認チェックを再度行ってください。確認済み条件・テンプレート確認は30日で再確認対象になります。この30日はアプリ独自の運用ルールです。

## 計算とデータの扱い

- 6市場（SG / MY / TW / PH / TH / VN）の通貨・国別設定を独立管理。**日本から各市場へ出店できることは保証しません**。特にベトナムを含む出店資格はショップで個別確認してください。
- 手数料を商品代金／商品代金＋購入者送料のどちらに課すか、販売・決済・サービス別に指定します。手数料への税、固定料、手数料控除後の送金費、広告費、返品引当を分けます。
- 内部計算はDecimal。JPY表示は小数2桁、損益分岐・目標価格はアプリの通貨刻みで切り上げます。税込・税抜や還付は入力条件で調整します。計算式と制限は [docs/FINANCE.md](docs/FINANCE.md)。
- 原価等が未入力なら利益を出しません。需要スコア・月間売上・ライブ相場・利益保証を作りません。カタログは着想であり市場データではありません。
- 2〜6商品の比較と、計算・観測情報からの理由整理に対応します。AIに判断を任せるスコアではありません。
- キーワードによるリスク確認理由は日本語・英語に対応します。未検出は販売可の意味ではありません。高リスクの表現等がある商品は承認・出力を止めます。
- 認証は個人ワークスペース共通のパスワード方式。複数組織の分離、ユーザー別権限、SaaS向けマルチテナント機能はありません。

## 旧版から移行

旧版のファイルを変更せず、入力CSV・下書き・ダッシュボード・仕入れトラッカー・追加出品情報を読み込みます。

```bash
python -m shopee_workbench import-legacy --directory /path/to/old/ai_side_biz
```

このリポジトリに残した旧版サンプルで試す場合は `--directory ai_side_biz`。**初回起動時にサンプルを自動登録しません。** SKU／商品名と国で重複をスキップし、再実行しても既存商品は上書きしません。旧承認・旧JPY売価・用途不明のsource_url・区分不明の送料はメモへ残し、再確認対象にします。旧承認状態をそのまま出品可能にはしません。送料を区分できない場合や現地売価を確定できない場合は空欄です。

旧Streamlit／未接続のNodeひな形は今回のブランチで置き換えました。過去のコードはGit履歴で参照できます。既存CSVは残してあります。

## バックアップ

画面の**設定 → JSONバックアップ**で商品と国別設定を保存できます。パスワード・APIキー・認証セッション・操作履歴は含めません。復元は空の環境のみ、全件検証後に一括処理し、既存商品を上書きしません。復元した承認・確認状態はリセットされます。

操作履歴を含む完全なDBバックアップにはSQLiteのオンラインバックアップAPIを使います。

```bash
python -m shopee_workbench backup-db --output /safe/path/workbench-backup.sqlite3
```

完全DBにはログインセッションも含まれるため、アクセス権を限定してください。復旧時はアプリを停止し、DBを置き換え、不要な `-wal` / `-shm` を**停止状態で**除去してから再開します。実運用では暗号化した保管先への日次バックアップと復元確認を用意してください。

## テスト

Pythonの標準unittestを使います。Node.js 24は画面ロジックテストのみに必要で、実行環境には不要です。

```bash
python -m unittest discover -s tests -v
node --check shopee_workbench/static/app.js
node --test tests/ui.test.mjs
python -m pip check
```

依存監査は `pip-audit -r requirements.lock`。GitHub ActionsでもPython 3.12 / 3.13、画面ロジック、依存監査を実行します。今回実行できた範囲は [docs/VALIDATION.md](docs/VALIDATION.md) を参照してください。

## Web公開

公開構成と手順は [docs/DEPLOYMENT.md](docs/DEPLOYMENT.md) にあります。最低限、**HTTPS、秘密情報の環境変数、永続ディスク、バックアップ**が必要です。Flask開発サーバーをそのまま公開しないでください。

```bash
docker compose up --build -d
```

Compose実行前に `APP_PASSWORD` と `APP_ORIGIN=https://あなたのドメイン` をホストの環境変数か未追跡の `.env` に設定します。Composeは `.env` を読み込みます。リバースプロキシでHTTPSを終端し、localhost:8000へ転送します。1インスタンス・1永続ボリュームの構成で運用してください。

未解決の仕様と確認元は [docs/OFFICIAL_SOURCES.md](docs/OFFICIAL_SOURCES.md)、既存版の調査結果は [docs/AUDIT.md](docs/AUDIT.md) に記録しています。
